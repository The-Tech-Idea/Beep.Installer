MCP Server

Beep.Installer.Mcp lets an AI client (Claude Code, Codex, any MCP client) drive Beep.Installer.exe over stdio. It is a thin wrapper: every command runs in the real executable, and the exit code comes back untouched.

Set it up

The MCP server is part of the installer: Beep.Installer.exe /MCP runs it over stdio, and an AI assistant starts it with that command. Running the installer normally never starts it.

In the advanced Package Builder, choose Project → AI / MCP. In the guided window, choose Tools → AI / MCP server…. The dialog shows the command and can add the installer to Claude Desktop, Codex and Claude Code; each registration backs up the client's file first and leaves its other servers alone. In this repository the project-scope .mcp.json does the same for Claude Code:

{ "mcpServers": { "beep-installer": {
    "command": "Beep.Installer/bin/Debug/net10.0-windows/Beep.Installer.exe",
    "args": ["/MCP"] } } }

The server runs commands through the same executable, so there is nothing else to install or configure.

Safety rules

  • Machine-changing commands (/S, /UNINSTALL, /REPAIR, /APPLYDELTA, /MSI, …) are refused unless dryRun=true (where the command really previews with /DRYRUN; /S and /REPAIR do not, so they always need allowMachineChanges=true) or allowMachineChanges=true. Publishing commands (/PUBLISHSDK=) are confirmed the same way. /UNINSTALL has no preview, so it always needs allowMachineChanges=true. /ALLOWSCRIPTCMDS is never offered: a person must pass it.
  • Credentials are never accepted as values. Options that carry one take only secret://env/NAME or env:NAME, resolved from the server's environment. Options that accept only a raw secret are blocked.
  • Arguments are a vector, never a joined string, so a path with spaces or quotes cannot inject another argument. Unknown options and missing required ones are refused before anything starts.
  • Windows and interactive commands (/LANGMGR, /UPDATEUI) are not offered; the child's stdin is closed so a command can never wait on a prompt.
  • Timeouts default to 300 s (max 3600 s) and kill the whole process tree.

Exit codes

CodeMeaning
0Success.
3010Success, reboot required — reported as success.
1The operation ran and failed, or a gate reported a blocking finding.
2The command line, script or response file was rejected before anything ran.

The result also carries stdout/stderr, parsed json when the command printed /JSON, timedOut, and problems when the request was refused before it started.

Where the command list comes from

The server, /CATALOG, the usage text guard and the CLI reference all read one file, Beep.Installer.Core/Cli/cli-catalog.json. Tests fail if a dispatched verb is missing from it, if one of its options is rejected by the argument validator, or if the reference page is out of date (regenerate with scripts/Update-CliReference.ps1).
