- Build output is reproducible enough to explain every input, hash and signer.
- Documentation includes a minimal example, enterprise example, failure recovery and breaking-change notes for dev-mode schema/runtime changes.

## Risks and controls

| Risk | Control |
|---|---|
| Feature breadth destabilizes working lifecycle | Capability slices; each exporter/provider behind conformance gates |
| Plugin ABI locks poor contracts | Keep SDK experimental through 1.1; contract tests and two-minor compatibility promise afterward |
| MSI and custom EXE semantics diverge | Treat MSI as exporter; publish capability report; use Windows Installer validators |
| Custom actions become a security bypass | Prefer typed providers; require permission declarations and policy approval |
| Secrets leak through authored projects/logs | Opaque secret references, central redaction, log scanning tests |
| Unplanned schema/runtime churn during dev | Prefer decisive replacement over duplicate paths; document breaking changes and provide canonicalizers only when they accelerate current development |
