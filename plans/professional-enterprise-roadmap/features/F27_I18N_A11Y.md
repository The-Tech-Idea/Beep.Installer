# F27 — Localization and Accessibility

**Outcome:** complete accessible authoring and install experiences, including Arabic RTL.

**Design:** resource every user string, ICU-like formatting discipline, RTL-aware layout, logical navigation, DPI-responsive containers, accessible names/roles/live progress, high contrast and reduced motion; localization is presentation only.

**Acceptance:** resource-key parity; Narrator and keyboard walkthrough; Accessibility Insights gate; Arabic 100/150/200% screenshots; no clipped controls; CLI JSON remains locale invariant. Depends on F25.

## Implemented slice — qualification evidence gate

The installer now has a first-class F27 qualification command:

```powershell
Beep.Installer.exe /QUALIFYA11Y=<source-root> [/OUT=<dir>] [/A11YEVIDENCE=<dir> /REQUIREA11YEVIDENCE]
```

It writes `a11y-localization-qualification.json` plus one diagnostics sidecar per scenario. The gate is source-root based so CI and release engineering can run it without opening WinForms.

Every run also writes a manual evidence capture kit into the output directory:

- `a11y-manual-evidence-manifest.json`
- `a11y-manual-evidence-checklist.md`

The checklist gives the controlled VM/device operator exact required artifact name tokens, allowed file extensions, capture instructions and pass criteria. This keeps manual Narrator, keyboard, Accessibility Insights and Arabic DPI evidence on the same `/QUALIFYA11Y` path instead of creating a separate review process.

## Implemented slice — manual evidence artifact quality

The strict manual-evidence gate now rejects placeholder attachments:

- Required evidence still uses the existing `/QUALIFYA11Y ... /A11YEVIDENCE=<dir> /REQUIREA11YEVIDENCE` path.
- Each required artifact must match the expected filename token.
- Each artifact must use a type-appropriate extension for notes, recordings, reports or screenshots.
- Empty artifact files fail the gate.
- The report records matched evidence metadata: requirement id, relative path, filename, extension, size and last-write UTC.
- The runner intentionally does not parse proprietary tool reports or image contents, avoiding a duplicate external review engine while still preventing empty/token-only evidence.

### Scenarios covered

| Scenario | Coverage |
|---|---|
| `resource-key-parity` | All shipped cultures (`en`, `ar`, `es`, `fr`, `de`, `zh`, `ja`, `pt`) must exist, expose the same keys and avoid blank values. |
| `arabic-rtl-readiness` | Arabic resources, RTL culture classification and mirrored wizard layout must be wired into the main installer. |
| `dpi-autoscale-readiness` | WinForms dialogs must opt into DPI autoscaling to avoid clipped controls at 125/150/200%. |
| `keyboard-screen-reader-readiness` | Shared accessibility helper must provide accessible names, tab-order normalization and wizard integration. |
| `high-contrast-readiness` | High-contrast mode must be detected and mapped to system colors. |
| `cli-locale-invariance` | Core build/plan/CLI logic must remain locale invariant and independent from UI culture. |
| `manual-walkthrough-evidence` | Optional strict evidence attachment for Narrator, keyboard-only, Accessibility Insights and Arabic 100/150/200% screenshots. |

### Response-file and modern aliases

Response JSON:

```json
{
  "qualifyA11y": "C:\\Repo\\Beep.Installer",
  "a11yEvidence": "C:\\Repo\\evidence\\a11y",
  "requireA11yEvidence": true,
  "out": "C:\\Repo\\artifacts\\a11y"
}
```

Modern aliases:

```powershell
Beep.Installer.exe --qualify-a11y=C:\Repo\Beep.Installer --a11y-evidence=C:\Repo\evidence\a11y --require-a11y-evidence
```
